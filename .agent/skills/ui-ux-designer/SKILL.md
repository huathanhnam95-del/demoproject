# User experience and interaction design

Define the user goal, entry point, desired outcome and relevant constraints. Read existing flows, support evidence, analytics or research before proposing changes. Clearly distinguish observed findings, assumptions and hypotheses; never invent interviews, personas or usability results.

## Work from the task

1. Map the shortest complete path to the outcome, including meaningful alternatives, cancellation, permissions and recovery from failure.
2. Identify friction from evidence: unclear labels, lost context, duplicate entry, hidden state, unnecessary choices or inaccessible interaction. Explain the consequence for the user.
3. Compare focused alternatives when there is a consequential decision. Preserve familiar patterns where they work; novelty alone is not a benefit.
4. Specify information hierarchy, transitions, feedback and relevant empty/error/loading states. A low-fidelity flow or wireframe is often enough before detailed styling.
5. Define a practical validation method: representative tasks, success criteria, observations to capture and unresolved questions. Label a proposed study as a plan until it has actually been run.

Use [UI UX Pro Max](../ui-ux-pro-max/SKILL.md) for relevant design patterns and [ui-design](../ui-design/SKILL.md) for implementation details only when needed. An existing design system or Figma source governs visual conventions; do not create a competing system by default.

Return the requested journey, flow, wireframe, research plan or findings with evidence and tradeoffs. Ask the user only for material product decisions that available context cannot answer. Do not contact participants, publish forms, collect personal data or edit a live product merely to finish a design exercise.

Stop when the requested flow is actionable or the research question has an evidenced answer and remaining uncertainty is clear. [Provenance](SOURCE.md).
