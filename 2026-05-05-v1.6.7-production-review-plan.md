# V1.6.7 Production Review & QA Plan

This document outlines the systematic verification steps required to ensure all changes in the `V1.6.7` release are stable and function as intended before pushing to production.

> [!IMPORTANT]
> Do not proceed with `/ship` or deployment until all sections below have been verified empirically in the local or staging environment.

## 0. Environment Setup (Local)
**Objective:** Ensure the local app + emulators are running in a production-like configuration for verification.

- [x] **Start local stack:** Start Firebase emulators + the local HTTPS server (default: `https://localhost:8443`).
  - *Recommended:* Run `npm run dev` (uses the persisted emulator data dir under `.local/firebase-emulator-data`).
- [x] **Use Chrome only:** Run browser checks in Chrome/Chromium only (Playwright `chromium` is acceptable for automation).
- [x] **Admin login (if required):** Use the admin account documented in `C:\Cursor AI\.local\browser-test-credentials.md`.

## 1. SPA Routing & Deep Linking Verification
**Objective:** Confirm that the Express catch-all routing, `<base href="/">` addition, and History API integration correctly handle SPA navigation without breaking asset paths or history state.

- [x] **Deep-Link Rendering:** Open a new browser tab and navigate directly to a deep-linked practice route (e.g., `https://localhost:8443/practice/writing/essay`).
  - *Verify:* The page loads successfully. No 404 errors for CSS or JS files in the network tab.
- [x] **History API Synchronization:** Click through at least 3 different practice modes using the sidebar navigation.
  - *Verify:* The URL updates immediately (e.g., `/practice/speaking/read-aloud/...`, `/practice/speaking/sgd/...`) without a full page reload.
- [x] **Browser Navigation:** Press the browser's Back and Forward buttons.
  - *Verify:* The UI updates to match the URL, and the correct practice mode panel becomes visible.

## 2. Write Essay Mode Remediation
**Objective:** Ensure the AI feedback system is fully restored and the UI is race-condition proof during the grading lifecycle.

- [x] **Submission Locking:** In Write Essay mode, type a response and click Submit.
  - *Verify:* All input fields and submit buttons are immediately disabled (UI locked) while waiting for the AI response.
- [x] **AI Grammar Scoring:** Wait for the AI assessment to return.
  - *Verify:* The rubric scores and grammar feedback load successfully without Firebase SDK dependency errors in the console.
- [x] **Try Again Flow:** Click the "Try Again" or "Next Question" button.
  - *Verify:* The UI unlocks, the text area clears, and the state resets completely without retaining stale feedback.

## 3. CRM Visa Automation
**Objective:** Verify that the early return bug in `student-modal.js` has been fixed and visa listeners successfully attach upon modal initialization.

- [x] **Modal Initialization:** Open the CRM Admin panel and open an existing or new Student profile modal.
- [x] **Visa Auto-Fill Logic:** Change the "Visa Type" dropdown to different values (e.g., Student Visa, Work Visa, PR).
  - *Verify:* The "Target English Level" and "Target Score" fields automatically populate with the correct derived values immediately upon selection.

## 4. CRM formatDateTime Reference
**Objective:** Confirm the `formatDateTime is not defined` console error has been eradicated across all CRM modules.

- [x] **Workspace Loading:** Load the CRM Leads and Students workspaces.
  - *Verify:* Timestamps (e.g., Created At, Last Modified) render correctly in the tables.
- [x] **Bulk Actions:** Perform a bulk archive or edit action in `lead-workspace.js`.
  - *Verify:* The action succeeds without throwing a `ReferenceError` for `formatDateTime` in the browser console.

## 5. PTE Write Essay Content Integrity
**Objective:** Verify that all 2,538 generated essay variants meet structural, lexical, and PTE scoring rubric compliance.

- [x] **Batch Integration:** 1,613 approved variants merged from `pilot-staging.json` to production database.
  - *Status:* Database confirmed at 2,538 variants.
- [/] **Gemma4 Scoring Audit:** Running `verify_essays_gemma4.py` on residual and newly merged variants.
- [ ] **Final Compliance Report:** Finalize the official verification report with >98% aggregate pass rate against PTE rubrics.
