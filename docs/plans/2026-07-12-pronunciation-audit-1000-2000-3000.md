# Non-Repeating Pronunciation Audit Campaign Implementation Plan

> **For Antigravity:** REQUIRED SUB-SKILL: Load executing-plans to implement this plan task-by-task.

**Goal:** Audit one reproducible set of 3,000 unique English words exactly once, producing cumulative accuracy reports at 1,000, 2,000, and 3,000 words.

**Architecture:** Generate one fixed-seed manifest from the unique alphabetic Oxford 5000 words that also exist in local CMU data, then split the manifest into three disjoint 1,000-word cohorts. Run each cohort once, preserve per-word evidence, and build the 1,000-, 2,000-, and 3,000-word reports by aggregating completed cohort artifacts rather than re-requesting earlier words. A resume ledger keyed by deployment version, algorithm version, manifest hash, and word prevents duplicate work after interruption.

**Tech Stack:** Python 3.10, `requests`, Flask/Cloud Run APIs, JSON/JSONL artifacts, Python `unittest`, npm scripts, Playwright Chrome.

---

## 1. Fixed decisions and invariants

- Sampling seed: `20260712`.
- Sampling frame: lowercase words matching `^[a-z]+$`, unique after case folding, present in both `The_Oxford_5000.csv` and `public/cmudict.json`.
- Manifest size: exactly 3,000 unique words. Generation fails if fewer than 3,000 eligible words exist.
- Cohorts are disjoint:
  - Cohort 1: manifest indices `0..999`.
  - Cohort 2: manifest indices `1000..1999`.
  - Cohort 3: manifest indices `2000..2999`.
- The 1,000-word report contains Cohort 1.
- The 2,000-word report aggregates Cohorts 1 and 2 without rerunning Cohort 1.
- The 3,000-word report aggregates Cohorts 1, 2, and 3 without rerunning Cohorts 1 or 2.
- CMU agreement remains corroborating evidence, not runtime truth.
- Every artifact records the base URL, Git SHA, deployment version, schema version, algorithm version, seed, manifest SHA-256, cohort number, start/end timestamps, and command arguments.
- A word may occur only once in the manifest, once in the ledger, and once across all cohort row files.
- HTTP retries must not create duplicate result rows; the final successful or terminal result replaces the in-progress ledger state atomically.
- Conflicted variants may remain as evidence but must never be scoreable or learner-selectable.

## 2. Acceptance gates at every checkpoint

The 1,000-, 2,000-, and 3,000-word cumulative reports must each satisfy:

- Zero HTTP 500 responses.
- Zero incorrect scoreable results.
- At least 98% validated coverage.
- Zero selectable conflict variants.
- Zero source-dialect violations.
- Zero explicitly non-US source-label violations.
- Zero graph/reference syllable-count mismatches.
- Zero duplicate words or duplicate result rows.
- Every unresolved disagreement fails closed.
- Every native graph shown to learners is rateable and count-consistent.
- Manifest hash and deployment/algorithm versions match across all included cohorts.

Any gate failure blocks promotion of the audit result. The failing word becomes a regression fixture before the audit resumes.

## 3. Output layout

```text
test-results/pronunciation-audit-3000/
├── manifest-3000-seed-20260712.json
├── ledger.jsonl
├── cohort-1-rows.jsonl
├── cohort-2-rows.jsonl
├── cohort-3-rows.jsonl
```

The manifest is immutable after the first cohort starts. Each report embeds only summary data plus references to its cohort row files; row evidence is stored once.

## 5. Campaign execution commands

Run against a no-traffic candidate revision first:

```powershell
$env:PRONUNCIATION_AUDIT_BASE_URL = "https://<candidate-url>"

python scripts/audit/pronunciation-reference-audit.py `
  --base-url $env:PRONUNCIATION_AUDIT_BASE_URL `
  --create-manifest test-results/pronunciation-audit-3000/manifest-3000-seed-20260712.json `
  --sample-size 3000 `
  --seed 20260712

python scripts/audit/pronunciation-reference-audit.py `
  --base-url $env:PRONUNCIATION_AUDIT_BASE_URL `
  --manifest test-results/pronunciation-audit-3000/manifest-3000-seed-20260712.json `
  --cohort 1 `
  --workers 6 `
  --output test-results/pronunciation-audit-3000/cohort-1-rows.jsonl

python scripts/audit/pronunciation-reference-audit.py `
  --manifest test-results/pronunciation-audit-3000/manifest-3000-seed-20260712.json `
  --aggregate-through 1 `
  --output test-results/pronunciation-audit-3000/report-1000.json
```

Review the 1,000-word gates and review queue before running Cohort 2. Repeat with `--cohort 2` and `--aggregate-through 2` for the 2,000-word checkpoint, then `--cohort 3` and `--aggregate-through 3` for the 3,000-word checkpoint.

## 6. Manual review protocol

At each cumulative checkpoint:

1. Review every row in `review-queue.json`.
2. Randomly select 50 validated scoreable rows from the newly added cohort using a second fixed review seed.
3. Compare displayed IPA, syllable count, primary stress, secondary stress, part of speech, dialect labels, and graph count with source evidence.
4. Play native audio for at least 20 reviewed rows, including diphthongs, rhotics, syllabic consonants, weak syllables, and alternate variants.
5. Record reviewer decisions and source links without altering raw audit rows.
6. Convert every confirmed defect into a regression fixture, fix it, deploy a new candidate, and restart only the affected cohort under the new deployment identity.

## 7. Final deliverables

- Immutable 3,000-word manifest and SHA-256.
- Three disjoint cohort row files totaling exactly 3,000 unique words.
- Cumulative 1,000-, 2,000-, and 3,000-word reports.
- Review queue and manual-review decisions.
- Machine-readable gate status at every checkpoint.
- A short Markdown summary comparing coverage, fallback rate, conflict rate, graph quarantine rate, and corroboration rate as the sample grows.
