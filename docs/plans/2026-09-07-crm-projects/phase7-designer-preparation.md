## Product flow

Owner selects Automate from current project. Manage shows a flat list, search/folder filters, enabled state, designated actor and current validation status. Create opens a readable When/if/then recipe with native accessible selectors. Advanced sequential actions, conditions, if/else branches and bounded delays appear as connected ordered blocks backed by the same persisted definition. Switching representation preserves node identities, typed values, branch order and hidden advanced data; a representation must not silently drop unsupported nodes.

Editing is a local draft until Save creates an immutable candidate version. Preview selects a current sample task and displays exact effects, including subtree moves leaving their parent, and reference warnings. Activate requires the matching fresh preview token/version/revision. Any relevant draft change invalidates local preview immediately. Server conflict preserves the draft and offers explicit refresh/repreview; no automatic overwrite or activation.

Manage supports disable, disabled duplicate, title/folder edits, new-version actor transfer to a current Owner, immutable version history, run/node logs and repair of missing references. Failed nodes expose useful bounded reasons; internal implementation payloads stay out of ordinary product controls. AI draft entry will reuse this editor in Phase9; do not imply an active provider during Phase7.

Scope changes invalidate all async callbacks and clear inaccessible content. A current Editor/Viewer does not see Owner controls. Preserve existing account/project selection and admin metadata/content distinction. Use current project status labels while storing stable keys and current immutable column IDs.

## Interface preparation from actual Phase6 source

All routes below are relative to `/api/projects/:projectId`, require current Owner and return the existing success envelope. Manage GET `/automations` and per-rule `/versions` or `/runs` use pageSize/cursor. Open GET `/automations/:ruleId` returns rule, selected version and repair diagnostics; optional versionId opens history. Save POST `/automations/:ruleId/versions` requires operationId, expectedRevision, full definition and explicit loaded actorUid. Omitting actorUid currently defaults to the authenticated Owner, so ordinary saves must preserve it explicitly. Actor transfer intentionally supplies another current Owner and creates a version.

Create POST `/automations` supplies operationId, title, folder and definition. Metadata/disable PATCH per-rule supplies operationId, expectedRevision and title/folder/enabled:false. Duplicate POST per-rule `/duplicate` supplies operationId and expectedRevision. Preview POST per-rule `/preview` supplies versionId and sampleTaskId; activation POST `/activate` supplies operationId, expectedRevision, versionId and returned previewToken. Activation always follows a fresh visible preview. Run detail GET `/automation-runs/:runId` returns run and action journals.

Actual-source gaps to resolve in Phase7: server-bound search/folder/enabled pagination (filtering one client page is insufficient); safe management actor/version projection; human-readable sample effects with resolved labels and before/after values; safe ordered run-node presentation. Preview after a delay is conditional on a future fresh snapshot and must be labeled accordingly, never promised as guaranteed. Broken-reference diagnostics remain visible and repairable even when preview fails.

Read-only preparation found two Phase6 lifecycle defects before closure: duplicate inherits the source candidateVersion, and a disabled save retains an obsolete candidate pointer. Root is tracking those for Phase6 correction and persisted regression; Phase7 implementation remains gated on closure.

UI modules should separate pure immutable definition operations, typed editor rendering and scoped API/controller state. Recipe and connected-block views are two renderings of the same in-memory definition; toggling views does not reconstruct or serialize a reduced recipe. Operations address stable nodeId, preserve nested branches and typed literals, and reject deleting the last required step until a replacement is supplied. Keep raw JSON and internal lease/token data out of product controls.

## Bounded implementation decisions for the approved phase

Use `automation-definition-editor.js` for pure clone/edit/find/insert/reorder/remove operations and `automations.js` for scoped state and native form rendering. The first module must never mutate Board/context objects. An optional renderer extraction is appropriate if the controller becomes too large. Automate belongs in the Board action bar; one flat sibling workspace contains Create/Manage and the editor, outside rebuilt task rows. Meaningful labels, keyboard-operable native selectors, focus restoration after targeted updates and no nested cards are required.

Board context is authoritative only when actorUid matches the signed-in UID, project matches selected content project, lifecycle is active, membership is Owner and filterOptionsReady is true. Add a narrow `onContextChanged` hook at busy/readiness and clear/authority transitions; invoke the designer synchronously when Access changes selection, then update it from settled Board context. Transient refresh may disable controls while preserving a draft in the same scope; role loss/account/project change clears inaccessible state. An Owner-only403 must refresh current Board authority rather than infer that all task content was revoked. Actual content404/401 continues through existing denial/account handling.

Loaded Board tasks are not a full project. Sample/explicit task selection uses bounded paginated title search with parentScope:all, then exact authorized GET for selected IDs. Member, section and column controls use current Board context. Unknown saved references remain labeled unavailable with an explicit replacement control, never silently replaced by the first option.

Extend rules list with normalized query/folder/enabled filters bound into its cursor. A bounded scan may return an empty filtered page with continuation; UI must allow continuing and not claim a complete empty result prematurely. Return active/candidate actor metadata from the corresponding immutable versions without copying raw histories. Validation not yet performed is visibly distinct from valid or broken; opening a rule checks diagnostics. Folder is a bounded plain string, including an explicit unfiled filter.

Preview presents an ordered safe effect projection: step identity, action label, resolved sample/target IDs and labels, changed fields with before/after values, recipient UIDs rendered through authorized member labels, section destination and subtree-root warning. Preserve the existing preview token/reference fence. Simulate sequential pre-delay field effects for display without writing tasks. Branch choice before delay follows the immutable sample used by the engine; after delay mark effects provisional because execution reads a future snapshot. No guessed future values are presented as guaranteed. Display visible condition-no-match and broken-reference states.

Manage includes metadata save, disabled duplication of the current version, explicit preview-backed enable, disable, current-Owner actor transfer by immutable version save, immutable history and ordered safe run/node statuses. Saving definitions always sends the loaded actorUid unless the user explicitly transfers it. Exact operation IDs persist across a failed/unknown acknowledgement retry; editing payload creates a new operation ID. Relevant edits, sample changes and schema/context changes invalidate preview immediately.409 retains the draft and requires reviewed refresh/repreview.

Acceptance adds independent persisted API tests for list filter pagination/cursor scopes and preview side-effect absence/projection, pure definition roundtrip and controller held-response tests, plus real Chrome recipe/block edits persisted identically, create/preview/activate/real execution, duplicate/disable/transfer/history/repair and role/account/project scope changes. Root remains the sole emulator owner; UI and backend work may proceed concurrently only with disjoint file ownership after Phase6 closure.

### Review refinements

On Owner403 immediately invalidate Owner-only designer content and pending callbacks before refreshing Board authority. A failed refresh must not restore the old Owner controls. Preserve independently authorized Editor task content. Classify AUTOMATION_NOT_FOUND, AUTOMATION_VERSION_NOT_FOUND, RUN_NOT_FOUND and missing task references as resource-level errors; they do not imply project-wide content denial.

Save/preview callbacks also bind a draft generation. Held preview followed by an edit or sample change cannot restore an obsolete preview; held save followed by further edits cannot overwrite the newer local draft. An outstanding create/duplicate/save acknowledgement must first be resolved by retrying its original immutable payload and operation ID before another mutation with changed payload is dispatched. Keep the newer local draft while reconciling the earlier operation; do not create duplicate rules or unintended versions to recover a lost acknowledgement.

Explicit tests cover Owner-to-Editor403 with subsequent failed Board refresh, each resource404 classification, held preview/edit, held save/edit and lost acknowledgement followed by new edits. These are additions to the approved phase's verification detail, not new user approval gates.

### Backend-to-UI DTO additions

Rules list accepts `query` (trimmed case-insensitive title substring, max200), `folder` (omitted means all, empty means unfiled, otherwise exact bounded folder string), and `enabled` (omitted/all, true or false). Preserve pageSize<=50 and use a bounded scan of at most200 records with continuation. Cursor scope includes every normalized filter plus current actor/project. Matching items add `activeActorUid` for enabled currentVersion, `draftActorUid` for candidateVersion or currentVersion, and `validationState:'not_checked'` until detail validation; never label unchecked references valid.

Preserve preview `effects` nodeId/type/payload for compatibility and add stable `path`, `sequence`, `target:{taskId,label}` where relevant, `changes:[{field,before,after}]`, `recipientUids`, `section:{sectionId,label}` where relevant, and `provisional` for effects depending on a post-delay snapshot. Only return safe task fields and already-authorized references. The UI renders this projection as plain-language changes; no raw payload/JSON panel. Existing warnings and token fields remain. Run display orders paths by immutable definition traversal and shows branch/delay/status/error information without internal leases or operation capabilities.

Expose a scoped `acceptDraft` entry for Phase9 that copies a proposed definition into the same unsaved editor only after matching current UID/project/Owner context. It never saves, activates or changes actor implicitly. Invalid/unsupported definitions produce a visible repair/error state and no effects. Phase7 shows no enabled provider or microphone control; later AI integration remains separately gated by Phase8 accounting and Phase9 confirmation.

Ordered recipient preview needs an explicit refinement: Phase6 validateReferences currently resolves every dynamic recipient against the initial sample, whereas engine notify preparation reads the current task after earlier actions. Thus an initially unassigned sample with assign-then-notify can be conservatively rejected, and a changed owner must be reflected in the new projection. Keep full static reference validation, but preview/activation sample evaluation must resolve reached dynamic notifications against the sequential projected task; branches before a delay still use the immutable initial condition snapshot. Add persisted assign-to-new-owner then notify and initially-empty-owner cases, proving preview has no writes and actual execution matches the shown recipient. Post-delay effects remain provisional. This is required Phase7 preview integration, not an engine execution claim already covered by Phase6 tests.
