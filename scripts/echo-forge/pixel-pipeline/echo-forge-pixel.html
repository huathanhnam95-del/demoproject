HOW THE 3D READ IS PRODUCED

Four techniques, all applied at render time rather than painted by hand.

Five-tone ramps, not two

Each material carries a five-step ramp from deep shadow to specular. Surface luminance picks the step, so curvature turns into banding that reads as volume.

One raked key light

A single light from upper-left-front shades every primitive consistently. Nothing is lit ad hoc, so all nine sprites agree about where the sun is.

Rim light on the turning edge

Surfaces angled away from the viewer pick up a bright fringe. This is what separates the figure from the background and sells depth more than any other single cue.

Contact shadow

A soft elliptical shadow pools under the feet. Without it a sprite floats; with it, it stands on the stage floor.

WHAT THIS MEANS FOR PRODUCTION

The build pipeline rasterises hand-authored SVG through Playwright into hash-verified PNGs. The renderer here emits a pixel grid, and a grid of solid cells is trivially expressible as <rect> elements — which is exactly what that sanitiser accepts.

Rig once, export every frame

Poses are joint positions, not drawings. New frames — enemy hit, defeat, victory — cost a few coordinates rather than a fresh sprite.

Resolution stays a decision, not a rewrite

If 64 reads better than 48 at 360px, re-export at 64. The contract canvas is 256, which divides evenly by 32, 48 is 5.33 — so 32, 64 and 128 stay pixel-exact.

Nine frames redrawn in place

Same four asset IDs, same canvas sizes, same frame counts. Only the SVG sources change, then --rebuild. Zero test edits.

Tints stay CSS

Three Wardens from one exported sprite by overriding the violet tokens on a data-warden attribute. No extra assets.
