# SRS (Spaced Repetition System) - Technical Logic & Architecture

This document provides a detailed breakdown of the upgraded SRS logic, including the dual-engine scheduler, algorithm specificities, and UI integration.

---

## 1. System Architecture

The SRS system operates as a modular architecture consisting of three main components:
1.  **SRSScheduler (srs-scheduler.js)**: The core "calculating engine." It is a standalone ES module that implements both SM-2 and FSRS. It is pure logic and does not depend on the DOM or Firebase.
2.  **SRSReview (srs-review.js)**: The "controller." It manages the review session, interacts with Firestore for data persistence, handles UI events, and delegates all scheduling math to the SRSScheduler.
3.  **UI Layer (index.html / srs-review.css)**: The user interface, now featuring a Settings Modal and a Chart.js-powered memory health graph.

---

## 2. Scheduling Engines (The Logic)

### A. Enhanced SM-2 Algorithm
The classic SM-2 algorithm has been upgraded with precision improvements similar to modern Anki implementations.

**Core Formula:**
- `New Interval = Current Interval * Ease Factor`
- `New Ease Factor = Max(1.3, Current Ease + Correction)`

**Improvements Made:**
1.  **Lateness Bonus**: If a card is reviewed late but correctly, the "Effective Interval" used for calculation is boosted: `EffectiveInterval = interval + daysLate * 0.5`. This prevents the system from "forgetting" long gaps of successful memory.
2.  **Fuzzing**: To prevent "card clusters" (many cards appearing on the same day), a random variance (95% - 105%) is applied to any interval greater than 2 days.
3.  **Hard Qualifier**: Pressing "Hard" now uses a fixed 1.2x multiplier and reduces ease by 15%, ensuring the word stays in tighter rotation without resetting progress.
4.  **Lapse Handling**: Pressing "Again" resets the interval to 0 (entering relearning) but applies a managed ease penalty (-20%).

### B. FSRS Algorithm (Integrated via ts-fsrs)
The system integrates the "Free Spaced Repetition Scheduler" (FSRS), which uses a 17-parameter model to predict memory decay.

**Core Formula (Memory Model):**
- `Retrievability (R) = 0.9 ^ (t / S)`
- Where `t` is elapsed days and `S` is Stability.

**Implementation Details:**
- **Stability and Difficulty**: These two parameters are stored in the word's `fsrs` metadata object.
- **Mapping**: Since the `ts-fsrs` library uses its own state enums, `srs-scheduler.js` handles bi-directional mapping between local card states (New, Learning, Reviewing) and FSRS states.
- **Mastery**: A word is considered "Mastered" if its FSRS Stability reaches 30 days.

## 3. Visualization Logic (Retention Forecast)

The "Memory Health" graph uses a histogram to show the current "Retrievability" of all words in the collection.

**Calculation Logic:**
1.  **For FSRS Cards**: Uses the native formula `R = 0.9 ^ (elapsedDays / stability)`.
2.  **For SM-2 Cards**: Since SM-2 doesn't track "Stability" explicitly, we estimate it: `Stability ≈ Current Interval`. The retrievability is then modeled as `R = 0.9 ^ (elapsedDays / Interval)`, assuming 90% retention was the target at the scheduled date.
3.  **Binning**: Cards are binned into five categories (<70%, 70-80%, 80-90%, 90-95%, 95-100%) to visualize the overall "safety" of the user's vocabulary memory.

## 4. Final Code Snippets (Core Components)

### SRSScheduler.calculate (The Wrapper)
This is the single entry point for all scheduling. It is robust against null data and provides a 1-day safety fallback if math fails.

```javascript
calculate(card, rating, algorithm = ALGORITHM.SM2) {
    try {
        if (!card) throw new Error("Card data is required");
        if (algorithm === ALGORITHM.FSRS) {
            return calculateFSRS(card, rating);
        }
        return calculateSM2(card, rating);
    } catch (error) {
        console.error("SRS Calculation Error:", error);
        return {
            ...card,
            interval: Math.max(1, (card.interval || 0)),
            nextReviewDate: new Date(Date.now() + 86400000).toISOString(),
            state: card.state || CARD_STATE.REVIEWING
        };
    }
}
```
